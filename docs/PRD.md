# 星云客服 · PRD（草案）

> 版本：2026-11-07 · 状态：**尚未整版确认**（由现有可运行 MVP 回写，供 vibe design 选款）  
> 团队：**沈凯杰、王瑞康**  
> 演示场景：虚构 **星云大学** 校园办事私有知识库

## 1. 目标

为企业内部客服文档问答提供**可溯源、可拒答、可转人工**的私有知识库助手，避免大模型幻觉与「答了却说不清依据」。

## 2. 用户与场景

| 角色 | 场景 |
|------|------|
| 终端用户 / 演示观众 | 询问在读证明、图书馆、宿舍报修、校园网等 FAQ |
| 课程答辩评委 | 观察引用卡片、空库拒答、转人工存根、密钥不下发浏览器 |
| 开发同学 | 本地启动门户 + Dify 引擎演示完整链路 |

## 3. 范围内（MVP）

1. **知识库问答**：对校园办事样例 FAQ 提问并返回答案。  
2. **强制引用展示**：有依据时展示文档名、相关度、片段（借鉴 RAGFlow 可溯源理念）。  
3. **空检索拒答**：库外/无依据时明确拒答，不编造；引导转人工。  
4. **转人工存根**：提交演示工单，仅本地回执（不派真实坐席）。  
5. **自研门户**：中文客服 UI；经本地代理调用引擎，API Key 不下发浏览器。  
6. **开源取舍**（详见 README）：  
   - **Dify**：运行时编排 / Chatflow / 检索底座  
   - **RAGFlow**：引用可溯源理念  
   - **FastGPT**：快捷 FAQ / 流程化问答体验  
   - **MaxKB**：内网私有助手形态  

## 4. 范围外（本阶段不做）

- 安装并并行运行 RAGFlow / FastGPT / MaxKB 全套引擎  
- 真实工单系统 / CRM / 支付  
- 多租户权限与审计后台（可后续）  
- 替换生产 `web/` 为某套设计（须 design 确认后进入 plan/build）

## 5. 关键验收（可观察）

| ID | 验收 |
|----|------|
| R1 | 问「在读证明如何办理？」→ 回答含 **一网通办**、约 **3 个工作日**，并可见引用来源 |
| R2 | 库外问题 → 拒答文案 + 可点转人工，不假装有依据 |
| R3 | 转人工 → 得到本地演示回执号 |
| R4 | 浏览器网络面板仅见 `/api/chat`，不见引擎 API Key |
| R5 | 设计选款：三套可打开原型供比较；**选定并确认前不替换生产门户** |

## 6. 非功能

- 本地可运行（Docker Dify + `nebula-cs` 门户 `:8787`）  
- 样例数据为课程虚构；UI 文案中文  
- 文档与 STATUS 跟随 vibe 流程维护
