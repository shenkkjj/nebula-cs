# 校园客服 · PRD

- **版本 / 日期**：v1.0 | 2026-11-14 · 已整版确认（取代 2026-11-07 的未确认草案）
- **项目形态**：重构 + 功能扩展（Web）
- **承诺宿主**：H1 = 本机 Windows 11 家庭版 + Docker Desktop（WSL2）+ Ollama + Python 3.12+；浏览器为 Chrome / Edge 最新桌面版，窗口宽 ≥ 1280px。答辩用这台电脑演示。

## 1. 用户与目标

- **目标用户**：学生和访客在门户里匿名提问；坐席接转人工的对话并补标准答法；管理员维护知识库、看审计、跑评测；课程评委看演示和报告里的指标。
- **核心痛点**（2026-11-14 实测，见 `docs/evidence/2026-11-14-baseline-probe.md`）：
  - 12 个口语化问题里，知识库有答案的 9 个，现有规则引擎一个都没答出来。
  - Dify 没在运行，本机也没配模型 key，没有生成式 AI 链路。
  - 开题第 8 页的坐席、管理员功能和第 9 页的评测对照都没有。
- **本次成功标准**：
  1. 换说法提问能答对并带引用；库外问题不编造、可转人工；用评测数字证明（§3.6）。
  2. 开题第 7 页的 4 个 Dify 失败点各有一项约束，能用故障注入测试和真实操作演示。
  3. 转人工有人接：坐席接管、回复、回写知识库、标记坏例，坏例进评测集。
  4. 报告各章有真实素材：架构、Chatflow 与提示词、约束层代码、三组对照评测表、界面截图。

## 2. 范围边界

- **本次必做**：
  - 问答引擎改为 Dify 1.19.0 Chatflow：DeepSeek 生成回答，本机 Ollama 跑 bge-m3 向量；导入现有 144 条 FAQ。
  - 自建网关约束层：出口引用校验、空检索强制分支、引用按文档去重、绑定自检、敏感信息打码。
  - 用户门户沿用 E5，新增澄清选项、坐席回复显示、知识库维护态。
  - 坐席工作台；管理后台（文档、自检、审计、参数、评测）；坐席和管理员登录。
  - 评测集、一键评测、三组对照。
- **明确不做 / 延后**：
  - 学生 / 教职工账号，以及按角色限制可见文档（2026-11-14 未选）。
  - 线上部署（用户：「做完再说」，到 release 阶段再定）。
  - 模型微调、LangChain（课程无硬性要求）。
  - 对接真实工单、一网通办、CRM；坐席排班。
  - 手机和窄屏适配。
  - 代写课程报告正文。
- **现有功能去留**：
  - 保留：E5 视觉与交互（流式、停止、主题 chips、引用卡、本机会话历史、新对话），转人工入口，敏感信息打码，`/api/health`。
  - 替换：`server/lite_engine.py` 的规则检索和 `server/proxy.py` 的规则改写，改由 Dify Chatflow 负责改写、检索和作答，网关负责约束。
  - 去掉：算式、单位、时间、翻译、润色小技能，借模型开放闲聊，`SW*` / `BX*` / `JY*` 办事进度存根，Render 免费部署主线。规则引擎留在 git 标签里，只作评测对照组 A。

## 4. 数据、外部依赖与已知约束

- **数据与隐私**：样例 FAQ 是虚构的。打码后的用户问题和检索到的知识片段会发给 DeepSeek 生成回答，其他数据只在本机。
- **外部服务与费用**：DeepSeek API，用户已有 key，按量付费。开发加约 10 次全量评测，估计几十元人民币以内，计划阶段查证报价。bge-m3 在本机运行，免费。
- **需要你亲自做的事**（计划阶段给具体步骤）：启动 Docker Desktop；安装 Ollama（或授权我用 winget 安装）；创建 Dify 管理员账号；在 Dify 里填 DeepSeek key；生成应用 key 和知识库 key 交给网关。
- **知情后的选择与代价**：引擎按用户选择以 Dify 为主（我推荐的是自建为主）。已知代价：演示电脑必须先启动 Dify；以后要线上演示基本只能租服务器；报告里的自研部分集中在约束层、坐席、后台和评测。
- **已查证事实**（2026-11-14）：
  - 本机 Windows 11 家庭版，内存 15.6GB；Docker Desktop 29.4.0 已安装（WSL2），未启动；Ollama 未安装；环境变量里没有模型 key。
  - FAQ 共 144 条，格式为「## 序号. 标题」加答案段落（`sample-kb/客服样例FAQ.md`）。
  - 改造前基线见 `docs/evidence/2026-11-14-baseline-probe.md`。
- **假设，以及不成立时的影响**：
  - Dify 1.19.0 能在本机 Docker Desktop 跑起来，DeepSeek 和 Ollama 插件能从 Dify 插件市场装上。首次部署要联网下载数 GB 镜像，国内拉 Docker Hub 可能需要配镜像加速。装不上就回到引擎路线重新决定。
  - Dify 的流式接口能拿到检索节点输出和引用信息，R-201、R-202 依赖这一点。计划阶段先做最小链路验证。
  - 答辩现场这台电脑能联网调用 DeepSeek。断网时只能演示拒答和坐席流程。

## 5. 已确认取舍

以下取舍随 v1.0 整版确认一并确认：

- **D1**：R-105 去掉开放闲聊和算式、翻译等小技能，非办事请求一律礼貌说明服务范围。理由：开题第 7 页写了「禁止静默裸模型兜底」，这些功能也是现在规则代码变乱的主要来源。
- **D2**：去掉 `SW*` / `BX*` / `JY*` 办事进度存根。数据是假的，开题里也没有这项。
- **D3**：R-304 坐席回写直接进知识库，不设审批；每次回写有审计，管理员可删除。
- **D4**：SEC-002 坐席和管理员必须登录。你没选的「账号与权限」是按角色限制能检索的文档；后台登录是防止任何人打开后台改知识库，不能省。
- **D5**：§3.6 的指标目标值。
- **D6**：R-504 需要你们人工判 30 道题。
